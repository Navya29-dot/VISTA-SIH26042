# VISTA Backend

VISTA - Vernacular Intelligence for Smart Teaching & Adaptation uses FastAPI,
SQLite, local Ollama authoring, Vosk speech recognition, and local IndicTrans2.

## Setup

1. Create `.env` from `.env.example`. The default database is a local SQLite file:

```env
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_MODEL=llama3.2:3b
INDICTRANS2_MODEL_NAME=D:\AIModels\indictrans2-distilled
INDICTRANS2_LOCAL_FILES_ONLY=true
```

2. Install Python dependencies:

```bash
pip install -r requirements.txt
```

3. Seed curriculum, topics, questions, and local languages:

```bash
python -m backend.seed_database
```

4. Run the API from the project root:

```bash
uvicorn backend.main:app --reload
```

The judge-facing frontend is the existing static page at
`C:\Users\navya\Downloads\vis\vista_project\frontend`. Serve it separately:

```powershell
cd C:\Users\navya\Downloads\vis\vista_project\frontend
python -m http.server 5173
```

It contains the Science Hindi/Santali audio demonstration and can upload a WAV
file to `/voice-bridge/offline`.

## Key Endpoints

- `GET /languages` lists the bundled Indian language codes.
- `GET /concepts` lists editable curriculum concepts.
- `GET /questions` lists database-backed questions.
- `POST /answer` stores attempts in SQLite and returns misconception remediation.
- `POST /explain` uses local Ollama when available, with a deterministic offline fallback.
- `POST /translate` and `/translate/offline` use local IndicTrans2.
- `POST /translations/draft` generates a bilingual worksheet/flashcard draft and stores it for review.
- `POST /translations/approve` publishes reviewed text and optional audio metadata; only approved rows are exported.
- `POST /speech-to-text` and `/speech-to-text/offline` transcribe a local PCM WAV file with Vosk Hindi speech recognition.
- `POST /voice-bridge/offline` performs the complete local voice bridge: Vosk speech recognition followed by IndicTrans2 translation.

The seed data lives in `data/curriculum_seed.json`, so judges can see and change topics without touching API code.

## Offline Vosk demo without a tablet

Download official Hindi and/or English Vosk models from the Vosk models page, extract them to a drive with free space, and set the matching paths in `.env`. Install the package in the same environment as the backend:

```bash
python -m pip install vosk
```

Configure one or both models:

```env
VOSK_MODEL_PATH=/mnt/d/AIModels/vosk-model-small-hi-0.22
VOSK_ENGLISH_MODEL_PATH=/mnt/d/AIModels/vosk-model-small-en-us-0.15
VOSK_SAMPLE_RATE=16000
```

The endpoint accepts mono, 16-bit PCM, 16 kHz WAV. Hindi is the default; select English with `language_code`:

```bash
curl -X POST http://127.0.0.1:8000/speech-to-text/offline \
  -F "language_code=en-IN" \
  -F "file=@teacher_phrase.wav"
```

Use `language_code=hi-IN` for Hindi. The returned `text` can be sent to the Flutter Voice Bridge or translated with the offline IndicTrans2 path. Browser microphone capture and Android Vosk packaging are separate device integration steps; the backend endpoint is the immediately testable desktop path.

For the complete desktop demo:

```bash
curl -X POST http://127.0.0.1:8000/voice-bridge/offline \
  -F "source_language_code=hi-IN" \
  -F "target_language_code=sat" \
  -F "file=@teacher_phrase.wav"
```

The response contains both the recognized Hindi `transcript` and offline `translated_text`.

## Adding Santali classroom recordings

The Flutter lesson currently includes Hindi and Santali recordings for Math and
Science:

```text
Hindi.mp4
Science.mp4
Hindi.wav
hindi santali.wav
Science.wav
Science santali.wav
```

The WAV pairs are used by the app:

- `Hindi.wav` -> `hindi santali.wav`
- `Science.wav` -> `Science santali.wav`

Choose Math or Science in the classroom topic selector. Each topic shows the
teacher's Hindi recording, the Santali text, and the Santali recording for the
student. Their labels and paths are declared in `vista_app/assets/content.json`.
Run `flutter pub get` and then `flutter run`; the app plays the recordings
locally and does not upload them.

The backend path remains: Hindi WAV -> Vosk transcript -> IndicTrans2 Santali
text. The Santali WAV is a separately provided playback recording; it is not
generated by IndicTrans2.

## Authoring and offline bundle workflow

Generate a draft (local Ollama is used when it is running; otherwise the deterministic fallback is stored):

```powershell
curl -X POST http://127.0.0.1:8000/translations/draft `
  -H "Content-Type: application/json" `
  -d '{"concept_id":1,"language_code":"sat"}'
```

After a native-speaker review, approve it and attach a recorded filename:

```powershell
curl -X POST http://127.0.0.1:8000/translations/approve `
  -H "Content-Type: application/json" `
  -d '{"translation_id":1,"reviewed_text":"...","reviewed_by":"reviewer","audio_filename":"1.mp3"}'
```

Put recorded files in `audio/` and reviewed worksheet/flashcard images in `worksheets/`, then build the tablet package:

```powershell
python -m backend.seed_database
python -m backend.export_bundle --language sat --audio-dir audio --worksheet-dir worksheets
```

Only rows with `review_status='approved'` are copied into the SQLite bundle. Audio recording, native-speaker review, and Flutter/device validation remain human/device steps; the backend does not synthesize or approve them automatically.

## Offline English-to-Santali translation

Install the IndicTrans2 dependencies from `requirements.txt`, then download and cache the model once while internet is available:

```powershell
cd "C:\Users\navya\Downloads\Vista\Vista"
python -m pip install -r requirements.txt
python -c "from backend.indictrans2 import translate; print(translate('Good morning', 'en-IN', 'sat'))"
```

After the model is cached, force completely offline loading in `.env`:

```env
INDICTRANS2_LOCAL_FILES_ONLY=true
INDICTRANS2_DEVICE=cpu
```

Translate a UTF-8 script file without starting the API:

```powershell
python translate_offline.py .\script.txt --output .\script_sat.txt
```

The API equivalent is `POST /translate/offline` with `{"text":"...","source_language_code":"en-IN","target_language_code":"sat"}`. The `1B` model needs several GB of disk/RAM; use a machine with sufficient memory for local inference.

`database_schema.sql` is included as a readable PostgreSQL reference for presentations and manual setup.

## Judge-Ready Prototype Features

- Browser live captions capture the learner's spoken answer in the selected language.
- Spoken answers are saved as `speech`, while typed answers are saved as `text`.
- VISTA normalizes answers before grading, so values such as `1/2`, `half`, and similar numeric forms are interpreted more realistically.
- Wrong answers are sent to the AI analysis layer for misconception, explanation, and reteaching method.
- The teacher dashboard shows recent student-teacher interactions from `/attempts`, including the learner answer, language, modality, concept status, and suggested remediation.
- Live captions work best in Chrome or Edge after allowing microphone permission.
